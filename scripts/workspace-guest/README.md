# First generation in the managed Linux guest

`build-image BASE.ext4 NEW.ext4 CORE_PACKAGE SQUASHFS_RUNTIME` builds an **inactive** root image. Run on a matching Linux image-build host with e2fsprogs and OpenSSL development headers, rsync, a compiler and mount privileges. Supply the checked Linux release package and x86-64 squashfs-tools 4.7.5 (`mksquashfs`, `lib/ld-linux-x86-64.so.2` and its matching libraries). The base must contain the maintained guest init and `/usr/local/bin/sifttext` pointing to `/opt/sifttext/sifttext`. The script preserves the guest agent, fsck and its scratch policy. It does not change a VM registration. Pair it with the gateway that refuses to dispatch on failed onboarding.

Boot mounts or recovers the existing work disk. Only a first `sifttext instructions /workspace/knowledge` on a detached, unindexed home starts a generation. Within that request Core first installs its Git excludes and seals the disk. It compares the complete authored byte stream with HEAD's two subtrees, verifies object availability and checks the staged file list. Only this private mount can reuse that result. The publisher unmounts the work disk. Inside a private namespace a new autoclearing Linux loop holds an exclusive open of that same block device (no new storage). Outstanding mounts, including detached ones, prevent this claim. The builder verifies the checkout with the superblock read-only, fences its source mounts, then permits writes only through the rollback intent directory. It streams ledger and node pages to the final private inode in contiguous batches as it builds the remaining projections. It releases the mount and device claim before public activation. It interns repeated ASCII tokens within each positional search segment using SQLite's own tokenizer. The publisher flushes the completed database and navigation before activation. Later writes use the ordinary incremental engine.

A failed seal, capture, stage comparison or private build discards the entire private generation and prepares on the writable work disk with normal Git discovery and disk-backed scratch. Neither route dispatches or replays the customer command. Dirty source signatures include their mount identity, so the disk fallback finishes its root query on the final overlay in private; the very same mount is then moved into place. The final query, link image, database and durable activation must all succeed before returning instructions. Ordinary errors restore the unpublished view; after a power loss, the saved intent and image rename distinguish rollback from a completed generation. A committed disk requires a root image that understands this layout; do not roll a published work disk back to an older, unaware init.
