# CLI output budget

Return what the caller needs to understand the outcome, locate evidence or choose the next safe action. Keep exact requested data, permission boundaries and mutation/recovery state. Delete duplication before compressing; compact output does not establish acceptance or low resource use.

## Current contracts

| Operation | Result and boundary |
|---|---|
| Help | `sifttext -h` is the operation/flag reference. The public standalone `check` was removed; submit owns the deterministic gate. |
| `read` | Original `node.md` bytes, with native file-safety bounds; no collection certification. |
| `instructions` | Entry path, `version` and `version_scope:onboarding_entry_and_order`. Read that entry and its selected methods, not a hardcoded six-child list. This version is not global acceptance. |
| `create` | Uncommitted UUID and path after layout/relationship bookkeeping. No global status normalization or whole-collection validation. Partial I/O failure preserves inspectable work. |
| `worktree` | Private draft path, immutable base SHA and durable `artifact_home`. Reuse owned drafts. Allocation from accepted main does not mutate a dirty or behind normal home. |
| `normalize` | Optional deliberate status editing: `unchanged`, or actual writes with before/after statuses and removed reason-field names. Partial/uncertain writes remain actionable. Not required preflight or acceptance. |
| `submit` | Customer `saved`/`recovered`, accepted commit, knowledge version, home and draft-removal result; failures distinguish `not_accepted`, `accepted_incomplete` and `unknown`. `semantic_check:deferred` is not a semantic pass. Preserve original args and journals for recovery. |
| `accepted` | Separate checked view: accepted commit, knowledge version, view path, `home_advanced:false`. |
| `advance` | Direct movement to already-accepted main: `advanced`/`current`, accepted commit, version and home. Not resubmission. A finishing failure can follow reader movement; dirty/unknown work remains protected. |
| `index` | Nodes/status/version for current parseable authored files, not publication certification. Ordinary retrieval refreshes too: no ritual index-before-query. |
| Search | At most 20 ranked hits, total matches, intact names/summaries, IDs/status, compact readable ancestor context, useful excerpts, version and path template. Applicable warnings are preserved; over-512-token warnings require explicit source reads, not clipping. |
| Outline | Requested shallow/full hierarchy, IDs, names/summaries, statuses/reasons/warnings, child counts, coverage, version and path template. Shallow expandable branches retain exact full-output token costs. `invalid_draft` is explicit when honest navigation is impossible, not successful empty coverage. |
| SQL | Exact requested columns/order/cells, NULL and numeric storage-class precision. No silent limit, deduplication or summary. One read-only SELECT, at most 1000 rows; narrow the query explicitly. |
| Init | Home, created flag, initial commit, copied count and pointer outcome. Existing recognized homes remain unchanged; empty setup does not imply working instructions. |
| Runtime/source | Verified runtime, or matching source identity/path/maintenance guidance. No retired developer binary is an operational prerequisite. |
| Update | Preserve release identities, consent, conflicts and recovery state; omit empty/redundant progress. `--local-status` is recorded, local, non-atomic inspection, not publication clearance. `--status` still checks releases and writes state. |
| Account | Allowlisted account/subscription outcome; never credentials. Login retains human browser/payment authority; offline Core remains unpaid. |
| Sync | Installed opt-in native Git queue controls and identity/ownership guards. Local status/enable/disable do not qualify authenticated cloud transport or install a runner. |
| Session evidence | Preserve capture/attachment/archive identities, backup consent and restore uncertainty without transcript or private-destination dumps. |

## Freshness is not publication

SQL/search/outline/index mirror current parseable uncommitted drafts, without a full-store Bend acceptance gate. SQL may expose cycles or missing relationships; outlines return `invalid_draft` where those defects prevent honest navigation. Malformed or unsafe source refuses, never stale or partial success. Raw generated files may be old until refresh.

Each worktree has its own SQLite cache. Refresh reuses unchanged hashes/records and updates dependent eager outlines; unchanged reads use read transactions, with one refresh producer per view and dirty-generation/boot-epoch repair. SQL refresh maintains outline consistency too. Compare command versions across retrieval surfaces: `authored-merkle-v2` is an opaque 64-hex authored-inventory identity, not a Git commit or JSON-file hash. Older formats invalidate once. Internal outline-view hashes and instructions' entry/order version have different scopes.

## Measure actual output and resources

Use a pinned assured build and ordinary CLI invocations in disposable homes. Record exact argv, source/runtime stamp, stdout/stderr and native CPU/RSS/process evidence. Do not infer fresh-agent behavior from a text walkthrough or replace use qualification with a test-suite invocation. Historical output-cull measurements and their original verification remain in Git history; they do not qualify this revision.

There is no universal CLI-wide output maximum. Full outlines, broad SQL and genuine diagnostics can be large. A safe loose bound for a concrete rendered output is tokens <= final UTF-8 bytes; count escaping and repetition. Input file safety caps are not an all-fields token budget. Submit's 5000 `o200k_base` ceiling applies to each content body, using the exact pinned vocabulary, regex and upstream BPE count semantics.

Guarded returns over 15,000 tokens require `-y`; this is not a global stdout+stderr cap or proof of validity. Normalize preflights its exact receipt before writing. Publication preserves its compact completion result even after a save. Some errors/notices remain outside that limiter. `SIFTTEXT_NO_UPDATE=1` removes opportunistic update notices from measurements, not explicit-update behavior.

SQL suppression remains:

```text
[<tokens> tokens suppressed] Re-run this sifttext sql command with -y to print them.
```

Select only needed fields, filter and limit discovery; use counts for counts. Never rewrite a requested evidence query silently. Start outlines shallow, expand only useful branches, and reuse unchanged source reads.

Full-submit and warm-SQL resource/latency targets remain unmet. No universal <=50 MB command-plus-children peak, sub-250 ms query, current Linux qualification or newly supported cloud/harness integration is claimed here.
