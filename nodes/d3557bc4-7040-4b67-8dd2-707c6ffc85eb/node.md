A client can help with local Core only to the extent its harness has authorized local file and command access. MCP compatibility alone is insufficient: Core delivers a CLI and native files, not an MCP server.

Use the client's current documentation to establish those capabilities, then follow the parent node's local entry, permission and return contract. Supply the exact verified command path and knowledge home; do not install integrations, change credentials or expose files by inference. If the client cannot access local files, use permitted manual excerpts for discussion and perform approved edits through the local pipeline elsewhere.

This is a capability checklist, not a claim that a named client has been installed or qualified.
