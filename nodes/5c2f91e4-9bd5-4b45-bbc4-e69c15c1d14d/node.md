## Recover the question

Start with the user's actual request, current question, intended outcome, known constraints and any previously selected direction. The user may know the domain without having read, authored or approved the agent-maintained notes. Do not assume either unfamiliarity or familiarity beyond what the conversation shows. Answer the specific question first; do not require the user to restate information already available.

## Restore relevant understanding

Choose useful sources based on the question. For a known subject, inspect its owner and local outline. When location is unclear, search for likely owners, then inspect matching source nodes. Check the actual coverage returned; an outline or search result is navigation, not the full evidence. Open the bodies, artifacts and applicable instructions needed to establish the current answer, its basis, authority, conditions and uncertainties. Follow a selected method and its required dependencies. If an authorized controller implements the optional local child Binary Reading Checks, read and follow it only when that integration is selected; otherwise use direct reasoning. Reuse unchanged reads, and expand only when a material gap, changed condition, conflict or useful alternative warrants it.

Treat stored conclusions as judgments for their stated question and conditions, not independent proof. Distinguish what the user said or selected, what an artifact records, what an agent inferred, and what a trial actually established. Preserve missing source wording as unknown rather than reconstructing it. Revisit earlier grounds when new evidence or a changed question could alter the answer; retain the limits of the evidence examined.

## Orient and continue

Give the smallest complete useful answer: the relevant origin, current understanding and status, why it matters, and any consequential uncertainty. Restore context without reintroducing the whole project or unexplained internal method names. Expand when a material context gap or human-owned choice requires it.

When a consequential choice still lacks enough understanding, read the child named Develop Understanding Through Interaction through this node's `children.order` and `children/` directory. Use a question, example or small reversible attempt as appropriate and return to this undertaking under the same authority. Reuse it if already loaded; if the purpose and relevant grounds are sufficient, proceed without an interview.

If the user wants action, continue the original authorized task without a redundant briefing. Select the next useful contribution from the current goal, evidence, dependencies and permissions—not merely depth, recency or open status. Missing evidence calls for investigation; an implementation or failing check calls for authorized repair; a necessary action beyond the grant calls for the specific human decision. Continue independent permitted work while a separate branch is blocked.

When knowledge changes materially, update its existing owner or expose a distinct development, preserving meaningful prior grounds. Before an authorized knowledge write, follow SiftText Commit and the established project write boundary. This Read procedure adds no write permission.

## Return and handoff

Return the answer or next action with its decisive basis and important uncertainty. Do not claim exhaustive discovery or infer completion from an intermediate result. Before a genuine context handoff, preserve the current question, useful sources, answer, unresolved issues, selected direction and executable next step through the existing owner and authorized Commit route. A context reset alone does not require a new knowledge record.
