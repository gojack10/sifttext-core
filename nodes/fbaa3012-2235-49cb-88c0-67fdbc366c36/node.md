Memory moves in four ways: push (force context into the window), pull (fetch a specific node on demand), read (see what is stored), and write (organize and save). SiftText gives you the right to all four and forces none of them.

You can push the whole binder in when you want everything up front. You can pull one exact node when you want a scalpel. You can read everything that is stored, with a trail of what was saved and why. You can write by hand, or let the model write under your gate.

Compare the alternatives. Automatic memory products force the push and hide the read: the system injects what it picked, and you cannot audit it. Manual notes apps force the write: you do all the filing yourself, and it rots the moment you stop. SiftText hands you all four levers and lets the model run them once you trust it, while you keep the right to step in.

This is the blocker that started SiftText. The existing memory tools were automatic, and there was no way to be sure they saved what mattered, or to see the decision behind a save. Control and observability were the missing piece. The point is not that you must manage everything. The point is that you can.
