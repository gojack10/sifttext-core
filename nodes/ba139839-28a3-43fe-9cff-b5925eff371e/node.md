## Check every promised operation

Read back every changed field, structure, status and reference needed to verify the authorized delta. Batch independent reads where supported and reuse unchanged context already read. Compare exact intended content or the approved transformation, actual UUIDs, resolved reference targets and native status effects. Inspect partial failures; tool-call counts or a successful receipt alone do not establish the result.

Apply the half-done test to every node touched by Persistence and Reconciliation:

“If a fresh agent read this affected node now, would it see the state promised by the authorized tree delta?”

An author's answer checks representation, not observed fresh-agent behavior. A missing promised operation makes the result partial. Identify and repair it within scope, then recheck the repaired fields and affected dependencies.

Common mismatches include an uncreated or undiscarded rejected probe; a skipped body edit; an intended scope edit applied to the wrong field; a graph edge replaced with a plain-text mention or unresolved placeholder; and a stale parent section repaired in the wrong location or left with a duplicate child table of contents.

## Review the affected state

Use these checks on the actual landed result, without assuming a defect exists:

1. Distinct failed attempts have visible native discarded owners where independently meaningful; do not introduce unsupported `ruled_out` metadata or hide multiple attempts in one prose blob.
2. Volatile conclusions are not duplicated across owners; parent prose does not enumerate children as a second directory. Use native child symlinks/order files and SQLite Queries for one-hop parentage. Replace direct parent/child links with structural language such as “read parent”, “read children” or “the child named X”.
3. Topology reflects contribution: do not confuse an alternative to a leader with a downstream substrate, or put lateral probes beneath an unrelated attempt.
4. Where an actual graph relationship is intended, verify the JSON-valued `see_also` target UUID and nonblank reason. Narrative citations alone are not graph edges; literal placeholders are not resolved references.
5. Compare landed statuses with the effective statuses derived from fixed-baseline native normalization and explicit requests, not raw pre-write markers. Documented node/ancestor activation is expected; unexplained differences require repair.
6. Affected parent, child and material forward/backlink consumers do not contradict the saved change. Meaningful earlier evidence remains recoverable; obsolete competing operative instructions are not left active.

## Repair and finish

For a concrete mismatch, identify its evidence and affected change, repair within the authorized delta or standing grant, and recheck corrected fields and dependent results. Another full review needs a reason: a new finding, changed source or failed verification. Do not invent a violation to keep searching. A substantive repair outside the grant returns to the sibling named Dialogue; suspend only dependent work and report the exact missing decision.

## Separate behavioral evidence

Report landed-field verification separately from fresh-agent navigation or continuation evidence. When a claimed behavioral improvement requires a trial, use a separately authorized read-only session without the repair conversation or expected answers. Supply the entry and user-facing questions; compare its reading path, answers, omissions and unsupported claims with an evidence-backed inventory prepared before the test. Missing trial or launch authority leaves that behavioral claim pending, not a failed saved-field check.

A failed trial returns specific defects for repair. Add a rule only when observed failure supports a missing or conflicting instruction. An author walkthrough is not that trial.

## Final report

Issue one completion or partial-completion report: affected nodes and actual writes, verification performed, supported defects and repairs, half-done/frontier results, exact remaining gaps and separate behavioral work. A large set can use a summary plus its complete execution record. Counts come from actual results.

Declare the authorized change complete only when all promised operations and affected continuation checks pass with no known blocking defect. Otherwise label it partial and identify omissions. Distinguish a draft, saved content, Git commit, checked publication, unfinished home/retrieval cleanup and independent use. Saved authorization is not execution of an external action.
