After you agree what to record, follow Worktree Publication to allocate a private draft and fixed baseline. CLI Operations describes creating a root named for your problem and children for independently meaningful pieces. Supply each node's scope and body with ordinary file edits; the create helper supplies structure, not reasoning.

Read node.md files directly. Outline Navigation shows their hierarchy, and Leviathan Search or SQLite Queries locate relevant nodes. There is no built-in web tree browser. You may refine names, scopes and bodies, add children or explicit references under the native grammar, and use an authorized external agent for proposals.

Inspect the actual draft, normalize permitted statuses and check the complete candidate before committing. Publish only through the authorized checked path. Keep rejected or interrupted work recoverable. A tree is a workspace that can evolve; one valid first contribution is not a finished answer to the whole problem.
