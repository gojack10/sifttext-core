After you agree what to record, follow Worktree Publication to allocate a private draft and retain its immutable base SHA; no separate baseline checkout is needed. Create a root named for your problem and children for independently meaningful pieces using native UUID/layout files or CLI Operations' optional create helper. Supply each node's scope and body with ordinary file edits; the helper supplies structure, not reasoning or collection certification. Drafts may be incomplete until submission.

Read node.md files directly. Outline Navigation shows their hierarchy, and Leviathan Search or SQLite Queries locate relevant nodes. There is no built-in web tree browser. You may refine names, scopes and bodies, add children or explicit references under the native grammar, and use an authorized external agent for proposals.

Inspect the actual files and complete diff, stage intended paths and commit. A worker returns commit/base/evidence/open issues; only the authorized publisher submits, passing explicit status intent to submit. Submit owns mechanical normalization and exact combined-candidate acceptance, not semantic approval. Optional normalization is not required preflight. Inspect a refusal, repair within the same authority, commit and resubmit without blind resets or changing frozen limits. Keep rejected or interrupted work recoverable. A tree is a workspace that can evolve; one valid first contribution is not a finished answer to the whole problem.
