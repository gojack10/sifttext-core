## Observed conditions

The parent preserves the complete earlier local Canopy procedure: explicit contracts, cause-grounded repair, human overrides and executor walkthroughs. The navigable-procedure method clarifies selective dependencies and complete responsibility branches. This local successor combines those responsibilities without requiring private authoring laws or forcing the executor to replay historical amendments. No behavioral improvement is established by this text.

## Inference and response

### Contract and authority

Apply when creating or changing agent prompts, skills or executable node procedures. Ordinary knowledge/evidence notes need grounded representation, not an invented workflow. Read the existing owner, selected current procedure, affected dependencies, actual request and relevant evidence. Reuse unchanged reads.

Recover the intended outcome, actors, inputs/tools, recipient, authority and completion. Preserve consequential human words and stated reasons. Separate observations, human requirements, the author's interpretation and proposed method. A preference is not a proven repair. A proposal request ends at review; preapproval and standing grants cover only their actual scope.

Assign each actual role and decision boundary without inventing intent. An unresolved role, purpose or consequential permission receives the specific clarification, not a fabricated default. Preserve the chosen interaction style and unrelated work. An instruction or tool name does not establish runtime capability or new authority.

### Compose the current procedure

Write the default route in dependency order. Each meaningful responsibility supplies its input, actor, action, useful output/evidence and continuation. State triggers and returns for investigation, dialogue, a reversible attempt, revision, completion, missing input, contradiction and human override. Ordinary decisions stay within the grant; a genuinely unresolved human choice returns to its owner.

A complete procedure may be a coherent set of meaningful responsibility branches. Each branch supplies its inputs, action, output and return. Require current methods before their governed actions, conditional methods when their trigger applies, and historical sources only when investigating their relevance. Follow the selected current method directly without replaying amendment history. Check this through required dependencies: a selective entry fails if every child imports the whole framework. A return continues the work rather than restarting onboarding.

Use existing owners for shared semantic and mechanical rules instead of duplicating them into competing methods. Structure follows actual responsibilities, not a fixed child count or token target. Supply enough instructions for the assigned reasoner to choose an implementation within authority; do not prescribe future project answers or require a node per command.

Preserve complete predecessors and the conditions motivating substantive changes. Supply a complete successor or selected branch set with one clear current route. A changing link alone is not a complete historical dependency snapshot. Keep prior versions available for investigation, not mandatory replay.

### Challenge and review

For repair, identify the observed incident, supported causes and the cause each proposed clause addresses. Remove unsupported clauses. Prefer removing or narrowing obsolete requirements when that solves the problem. Generalize only as far as the evidence supports; preserve genuine deployment-specific conditions. If cause is uncertain, propose a discriminating check rather than claim the preferred method is proved.

Walk entry to exit for the triggering case and a materially different applicable case, considering the least-capable intended executor. Include a conditional branch, a human override, a revisable agent-selected method and a binding human constraint. Check actual available inputs, required reads, missing-input behavior, role/output/recipient/return and false-completion paths. Do not rely on a stronger model to fill gaps.

Inspect the real hierarchy and one meaningful descent. Useful findings under rejected approaches remain accessible. Apply Deslopifier to authored prose without weakening evidence, safety, authority or exact source words. Review the actual applicable dependency set rather than only the first node. A walkthrough is a text review, not a fresh-agent trial.

### Exact presentation and adoption

Show the actual affected tree, effective statuses, complete new bodies and exact changed fields through local Commit's current Dialogue route. For bounded edits show a contextual diff; for a whole responsibility show its complete replacement. Expose entry, roles, dependency/reference operations, returns and compatibility consequences together. A summary, method name or file link alone is not the actual change.

Present the problem and consequential choice at the level the human needs to steer; do not manufacture reapproval for settled decisions. Clarify an ambiguous override while preserving its scope and unmentioned constraints. Missing ownership, input or authority stops dependent work, not independent permitted work.

Return one coherent candidate to the invoking author/reviewer. Save only through SiftText Commit and the actual grant; returning there does not restart unchanged authoring stages. Preserve the predecessor before selecting the checked successor. Separate authored content, saved selection, delivered bundle, installed behavior and fresh-agent evidence. No evaluation, model launch or publication follows from authoring alone.
